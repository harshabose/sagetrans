| O-04 | ANSWERED | `Q_TRANSITION_MS` (clamped 500–30000 ms), timer starts when airspeed > AIRSPEED_MIN and assistance is off. | O-11 | PARTIAL | POSITION1 builds a velocity profile `v = sqrt(max(0, d − pos2_dist)·2·Q_TRANS_DECEL + v_pos2²)`, bounded by `pos1_speed_limit` (and ≥ 2·Q_WP_SPD), feed-forward accel = −min(accel_needed, 2·Q_TRANS_DECEL). | O-12 | ANSWERED (parameter names and units differ by release) | The vertical (Z) loop of the VTOL phases is `AC_PosControl::D_update_controller()`. Chain: P on position error (`Q_P_D_POS_P`, 4.7 name `Q_P_POSZ_P`; Plane-build default 1.0, range 0.5 to 4) gives a velocity target, limited by `Q_PILOT_SPD_UP` (2.5 m/s; `Q_PILOT_SPD_DN` 0 means use UP) and `Q_PILOT_ACCEL_Z` (2.5 m/s^2). A velocity P (`Q_P_D_VEL_P`, 4.7 `Q_P_VELZ_P`; default 5.0, range 1 to 10; I = D = 0; error filter 5 Hz) gives an acceleration target. An acceleration PID then acts on the **measured, gravity-compensated vertical acceleration** (`Q_P_D_ACC_P` 0.03, `_I` 0.1, `_D` 0, `_IMAX` 0.8, error filter 10 Hz; the file says the 4.6 and 4.7 values are 10 times larger, so `ACCZ_P` 0.3 and `ACCZ_I` 1.0). The output is a normalised thrust, turned into throttle with angle boost. There is no hover feed-forward: `D_init_controller` sets the integrator so the output equals the current throttle. The Plane defaults are the `APM_BUILD_ArduPlane` block of `AC_PosControl.cpp`. | The repo altitude hold (one PI on climb rate: `K_h` 0.5, `K_vh` 0.02, `K_i` 0.01, plus a hover throttle feed-forward) is a much weaker structure. The ArduPilot velocity P is equivalent to about 0.18 throttle per m/s on the Sage vehicle (VEL_P x mass / (dT/d delta) at hover), about 9 times `K_vh`. In scratch runs (AIRBRAKE exit, 32-scenario ensemble, no lift information given to the controller) the default loop holds the altitude to 0.5 m (p95) with ideal actuators and 0.8 m with a 0.25 s lag. This largely resolves DEC-6: the autopilot measures acceleration, not lift. See C_fix_spec.md. |
| O-13 | PARTIAL (read in source, not run) | Z controller in APPROACH and AIRBRAKE. `QuadPlane::vtol_position_controller()` calls `hold_hover(0)` in AIRBRAKE and then, in the "height control" switch, `D_relax_controller(0)` for APPROACH and AIRBRAKE when `transition->complete()` (state DONE). `D_relax_controller` re-initialises the Z controller every tick and decays the throttle set point toward 0 with `POSCONTROL_RELAX_TC` = 0.16 s (the source comment: 5% in half a second). `set_state(AIRBRAKE)` zeroes the acceleration-PID integrator, but the next `D_init_controller` sets it back to the current throttle. After the 1 s minimum airbrake the rotors are therefore near idle (`Q_M_SPIN_MIN`), not carrying W - L. POSITION1 then runs the Z controller from that state with the altitude target set to the altitude at the exit. | Corrects the reading of O-03 ("hold_hover(0)") and D's entry state (`airbrake_entry_state` spins the rotors up to W - L): the exit state is rotors near idle. Effect on D in scratch runs with the ArduPilot Z loop: p95 excursion 0.50 m from an idle start against 0.40 m from a W - L start; the at-limit stop is unchanged (66 m, 13.4 kJ). Needs a SITL or log check of the rotor throttle during AIRBRAKE before it is relied on. |

| O-14 | ANSWERED | The airspeed of the forward transition is **equivalent airspeed**. `SLT_Transition::update()` reads `ahrs.airspeed_EAS()` (master, `Plane-4.7.2`; `airspeed_estimate()` in `Plane-4.6.3`, the same quantity under its old name; the true-airspeed accessor is a separate function). The repo controller compares TRUE airspeed (`controller.yaml` says so), which at 5000 m puts the threshold 7 % lower in EAS than intended. Q2 already reads it as EAS. |
| O-15 | ANSWERED | The exit threshold is `max(AIRSPEED_MIN, Q_ASSIST_SPEED)`, and assistance can restart the transition. `should_assist` raises `speed_assist` the moment `aspeed < Q_ASSIST_SPEED` (no delay; `Q_ASSIST_DELAY` applies only to the altitude and angle triggers). At the top of `update()`, if assistance is wanted and the transition is not forced, `transition_state` is set back to AIRSPEED_WAIT **even from TIMER**. AIRSPEED_WAIT then runs `hold_hover` again. TIMER can only be entered with assistance off. `Q_ASSIST_SPEED` of 0 or -1 turns the speed trigger off. `Q_ASSIST_ALT` (altitude above ground below which assist triggers) and `Q_ASSIST_ANGLE` (default 30 deg; attitude error outside the envelope) restart it the same way after `Q_ASSIST_DELAY` (0.5 s). | A dip of EAS below `Q_ASSIST_SPEED` during the fade puts the rotors back at hover thrust. The forward analysis needs a flag for this (fade restarted). Setting `AIRSPEED_MIN` below `Q_ASSIST_SPEED` has no effect. The register value of `Q_ASSIST_SPEED` matters for the forward half, not only for C's entry speed. |
| O-16 | ANSWERED | **Pitch is capped during the forward transition.** `set_FW_roll_pitch` (auto-throttle modes only): in AIRSPEED_WAIT the limit is `Q_TRAN_PIT_MAX` (default **3 deg**; 0 deg while ground speed is below 3 m/s); in TIMER it is `(Q_TRAN_PIT_MAX + 1)·2` (**8 deg** at the default). The limit is symmetric and is also set as the TECS pitch limit. It disappears at DONE. In other modes (FBWA, QHOVER with pilot input) there is no such cap. | The wing's angle of attack in the transition is `theta - gamma` with theta capped at 3 then 8 deg. This is first-order for the forward analysis and is not in the register or the repo controller (its cruise stub allows 0.15 rad). Add `Q_TRAN_PIT_MAX` to `controller.yaml` and decide whether it is a searched variable. |
| O-17 | ANSWERED | **Pusher throttle in the forward transition (AUTO, separate lift thrust).** `apply_throttle_limits`: while `in_frwd_transition()` (assisted flight and state AIRSPEED_WAIT or TIMER, not AIRBRAKE) the maximum is `TKOFF_THR_MAX` if non-zero (else `THR_MAX`) and the minimum is `max(THR_MIN, TKOFF_THR_MIN)`, or `TRIM_THROTTLE` if `TKOFF_THR_MIN` is 0. TECS then demands throttle inside that range. TECS sees the real airspeed (`use_synthetic_airspeed` only forces airspeed mode on), so it saturates at the maximum while the speed is far below `AIRSPEED_CRUISE` and backs off near it. Battery-voltage compensation (`fwd_batt_cmp`) relaxes the limits and `BATT_WATT_MAX` can cut them. | The pusher cannot go below cruise trim throttle during the transition, and it is not a fixed `TKOFF_THR_MAX` (the repo's `fwd_wait` and `fwd_fade` hold `tkoff_thr_max` flat). Model it as a clamp on a TECS-like speed demand. `TKOFF_THR_MAX` in AUTO applies in this stage only because of this branch. |
| O-18 | ANSWERED | **Control structure by phase.** AIRSPEED_WAIT: `hold_hover(climb_rate)`, the hover Z loop (O-12) with climb-rate demand `altitude_error_cm·0.1` (error spread over 10 s, ramped in over 2 s after the Z controller starts, clamped to the pilot speed limits; `Q_OPTIONS` LEVEL_TRANSITION caps it at 0 or below). TIMER: `hold_stabilize(throttle_scaled)` with `throttle_scaled = last_throttle·(T - t)/T` (floor 0.01), no Z loop, throttle mix 0.5·scale; `last_throttle` is the rotor throttle at the **last step of AIRSPEED_WAIT**. Outside VTOL modes the rotor attitude loop follows the **fixed-wing** rate targets (`multicopter_attitude_rate_update`), so pitch is driven by the fixed-wing pitch controller from the TECS pitch demand. Altitude during the fade is therefore held by TECS (pitch at most 8 deg, pusher within O-17), not by the rotors. DONE: spool SHUT_DOWN and the pitch cap lifts. | `last_throttle` is hover throttle minus what the wing already carries when EAS crosses `AIRSPEED_MIN` (the Z loop acts on measured acceleration), so `AIRSPEED_MIN` sets the wing's share at the hand-over and the starting level of the open-loop fade. The repo keeps altitude hold running during the fade (O-04 already flagged this) and has no TECS pitch loop. A forward model needs: the Z loop until the hand-over, a frozen-throttle linear fade, a TECS-like pitch and pusher loop with the caps above. |
| O-19 | PARTIAL | TECS defaults, identical in `Plane-4.6.3` and `Plane-4.7.2` (4.7 adds `TECS_THR_ERATE`, O-10): `TECS_TIME_CONST` 5 s, `TECS_THR_DAMP` 0.5, `TECS_INTEG_GAIN` 0.3, `TECS_VERT_ACC` 7 m/s^2, `TECS_HGT_OMEGA` 3, `TECS_SPD_OMEGA` 2, `TECS_SPDWEIGHT` 1.0, `TECS_PTCH_DAMP` 0.3, `TECS_CLMB_MAX` 5 m/s, `TECS_SINK_MAX` 5 m/s, `TECS_PITCH_MAX` 15 deg, `TECS_SINK_MIN` 2 m/s. The structure (specific total energy for throttle, energy distribution for pitch) was not traced line by line. `THR_MAX`, `TRIM_THROTTLE` (called THR_CRUISE in code), `PTCH_LIM_MAX_DEG` and `AIRSPEED_CRUISE` defaults are compile-time constants not read. | A reduced TECS (these gains, the clamps of O-16 and O-17) is a model assumption to calibrate against a log or SITL run. After DONE the recovery from a height or sink error is limited by `TECS_VERT_ACC` and `TECS_CLMB_MAX`, which is what the end-of-fade criterion should use as the available recovery acceleration. |

## Concrete code changes implied
1. `BaselineController` switch test: `d ≤ V_ground²/(2·a_plan) + 2·V_closing`; drop `speed_test="air"` from the baseline.
2. Insert the AIRBRAKE stage (1 s minimum, TECS pusher, hover-hold rotors, exit conditions above) between cruise and Position1.
3. `theta_limit`: start the ramp at `max(last_fw_nav_pitch, 0)`; add the nose-down envelope.
4. `theta_B` as a function of airspeed, `Q_BCK_PIT_LIM·(V_min/V)²`, active only for the NEW forward-throttle scheme.
5. Forward-transition fade: frozen `last_throttle`, linear, open-loop, floor 0.01.
6. 0.5 s rotor spool lag from rest; `MOT_SPIN_MIN` default 0.15.
7. Altitude hold: the ArduPilot-structured Z loop (O-12) as the baseline for C, with the default gains above (C_fix_spec.md, section 3).
8. `airbrake_entry_state`: an option for rotors near idle at the exit (O-13) (C_fix_spec.md, section 4.1). D's default is unchanged until the owner decides.
9. Forward transition (O-14 to O-19): compare EAS with `max(AIRSPEED_MIN, Q_ASSIST_SPEED)`; Z loop until the hand-over, then a frozen-throttle linear fade; TECS-like pitch (cap `Q_TRAN_PIT_MAX` then `(Q_TRAN_PIT_MAX + 1)·2`) and pusher (clamp `[TRIM_THROTTLE or TKOFF_THR_MIN, TKOFF_THR_MAX]`); flag a fade restarted by assistance.
10. Pin `Plane-4.7.2` for O-08: the transition functions read here are identical to master.
