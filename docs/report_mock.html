What to take from it

Up to Q_TRANS_DECEL 2.25 the two ramps give the same stop; the profile, not the ramp, limits the braking. Past 2.5 the register ramp starts to overshoot and the searched ramp does not.

At the same 39 m, B1 needs a third less energy than C. That gap is the price of the autopilot's structure.

What not to take from it

B1 is one scenario, open loop, and it knows the scenario exactly. It is a reference, not a controller.

B1 depends on the wing limit. Without any limit it reaches 7.1 kJ with the wing at 51°, which needs a post-stall model nobody has checked, so it is not plotted.

How the two stops differ in time

Hover a panel to read all three runs at the same instant. C's altitude loop drives the rotors to 0.41 throttle within half a second; B1 keeps them at 0.03 to 0.06 and lets the wing work at its lift limit before it brings them in.

Package

What a run writes

The report is the entry point. Tables and data stay available, but nobody has to open them to read the results.

  • report.html this page, one self-contained file that opens by double-click
  • report.md the same text without figures, for diffs in git
  • settings.html the recommended-settings sheet on its own, one page to print
  • figures/ every figure as SVG and PNG, with the run record line in the footer
  • tables.xlsx one sheet per table, an index sheet first, units in the header row
  • tables/*.csv the same tables for scripts
  • headline.json the numbers the proposal quotes, each with its source table
  • run_record.json hashes of inputs and of every file above
